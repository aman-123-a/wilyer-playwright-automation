## 4. Scheduling suite data (`QA_SCHED_`)

**Fixture built once per run:** a new playlist containing **one zone with three items** —
2 image files + 1 campaign — created through the editor UI (`buildTwoImageSlideZone()` then a
campaign dragged in). The campaign is seeded via API as `QA_CRUD_Sched_w<worker>_<rand>`.

### Schedule windows

| Constant | Value | Maps to |
|---|---|---|
| `DEC` | `2026-12-01` → `2026-12-31` | Case B "1 Dec to 31 Dec" |
| `OFFICE` | `09:00` → `17:00` | Case A "9 AM to 5 PM" |
| `JAN` | `2027-01-01` → `2027-01-31` | Case E seasonal layout |
| `MON_TO_FRI` | `monday, tuesday, wednesday, thursday, friday` | Case A "Mon to Fri" |
| past window | `2020-01-01` → `2020-01-31` | Case F "nothing in schedule" |
| inverted range | `2026-12-31` → `2026-12-01` | SCH-V2 boundary |

### Schedule payload shape (as the server stores it)

```json
{ "startDate": "2026-12-01", "endDate": "2026-12-31",
  "startTime": "09:00",     "endTime": "17:00",
  "isRoutineEnabled": true,
  "days": { "sunday": false, "monday": true, "tuesday": true,
            "wednesday": true, "thursday": true, "friday": true, "saturday": false } }
```

`null` = no schedule = always on. Helpers: `schedule()`, `days()`, `ALL_DAYS`, `NO_DAYS`,
`WEEKDAYS`, `WEEKENDS` in `api/services/PlaylistService.ts`.

## 5. Sub-user RBAC suite data (`QA_SUBF_`)

Names: `QA_SUBF_<label>_<timestamp>_<rand>` — e.g. `QA_SUBF_Create_1785302…_k3f9x`.

### Folder-placement cases (SUBF-010…016)

| Case | `folderId` sent | Expected |
|---|---|---|
| assigned folder | sub-user's folder id | `200` |
| unassigned folder | an admin-only folder id | `403` "Access denied to this folder." |
| root | `null` | `403` "You can only create campaigns inside a folder you have access to." |
| omitted | *(field absent)* | `403` — same message |
| empty string | `""` | `403` — same message |
| malformed | `"not-an-objectid"` | `403` — same message |
| unknown, well-formed | `"000000000000000000000000"` | `400` "Folder not found." |

### Boundary values

| Field | Values tested | Result |
|---|---|---|
| `name` | `""` | `400` `"name" is not allowed to be empty` |
| `name` | `"A"` (1 char) · 256 × `N` · 1000 × `N` · `"   "` (whitespace) | all `200` — no max length, no trim |
| `defaultDuration` | `0`, `-5`, `2.5`, `999999` | all `200` |
| `data` | `[]` (zero items) | `200` |
| `data[].file` | `000000000000000000000000` | `200` — no referential integrity |
| `data[].file` | `6a6335c662dca4bcc662d41d` (foreign media) | `200` — **BUG-SUBF-01** |

The fixed-length name cases (`A`, 256×N, 1000×N, whitespace) **purge by exact name before and
after** the assertion, because campaign names are unique per folder and a fixed name would
otherwise report the next run's duplicate `400` as if it were length validation.

## 7. Data created, and cleanup

Every suite creates **only** prefixed artefacts and removes them in `afterAll`, sweeping each
folder it touched as the identity that owns the data (a sub-user's campaign must be deleted by
the sub-user or the admin, not by a foreign token).

**Pre-existing data left untouched:** 48 campaigns at the admin root, 3 in Meerut, 5 in Noida,
and every folder, playlist and media file listed above.

### One residue incident, and the fix

The first version of the length case generated names as `Q` + 254/255 × `N` — no prefix — so the
`QA_RT_` sweep did not match them and **2 campaigns were left on the server**. Found by dumping
the live campaign list while compiling this document, then deleted with a pattern narrow enough
to hit only my own artefacts (`/^QN{200,}$/`, 255 and 256 chars). `nameOfLength()` now carries
the prefix, so the case is self-cleaning.

The lesson is recorded because the earlier "no residue" check was **too narrow** — it looked for
`QA_RT_`, `QA_SUBF_` and `PROBE_` only, so it reported clean while these sat there. A residue
check should list what is actually present and be read, not just grep for expected prefixes.

## 8. Fixture drift — do not hardcode

The shared server is reconfigured between sessions. Observed in three days:

| When | Change |
|---|---|
| 2026-07-28 | sub-user assigned to **Noida** only |
| 2026-07-29 (morning) | sub-user assigned to **Meerut** only — and Meerut holds **0 media** |
| 2026-07-29 (later) | sub-user sees **both** Meerut and Noida |

Consequence: a sub-user cannot always pick media from its own folder. Campaign creation still
succeeds in that state only because item media is not scope-checked — **BUG-SUBF-01**, which is
a defect, not a fixture the suites should rely on.

All three suites therefore resolve folders, media and playlists at run time and assert on
relationships ("the folder the sub-user is assigned to", "a folder the admin has that the
sub-user does not") rather than on ids.
